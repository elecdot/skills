# Write Better English

Produce copy-ready English from settled ideas. The source owns the ideas; edit
their expression, not their content.

## Editorial pass

Scale the work to the text's length, uncertainty, and risk. Keep this pass
internal for routine work; a short, well-specified request should receive a
direct answer rather than a process report.

1. **Ground.** Identify the artifact, intended reader, register, and purpose.
   Read directly relevant local context when it can establish terminology or
   meaning. Ask only when missing information would materially change the
   result.
2. **Reconstruct.** Account for every source proposition and its logical
   relationships. Make implicit subjects, references, cause, contrast,
   conditions, sequence, or scope explicit when the source strongly supports
   them. Do not brainstorm claims for the author.
3. **Write.** Produce natural, unmarked English suited to the artifact. Freely
   restructure wording and sentences while preserving the author's voice.
   Do not make the text more formal, verbose, or generic than its context
   calls for. Preserve the artifact's structure and markup unless asked to
   change them.
4. **Audit.** Verify that every source proposition has a destination; facts,
   logic, stance, certainty, names, terms, citations, code identifiers,
   numbers, and versions remain intact; and every explicitation is supported
   by the source. Remove unsupported additions and residual source-language
   logic. Do not silently correct suspected factual errors.
5. **Deliver.** Follow the applicable protocol below.

If competing interpretations would materially change a fact, logical
relationship, stance, degree of certainty, reader, or requested action, ask
the user. Resolve ordinary wording choices yourself. Offer multiple versions
only for a genuine semantic or register fork, and explain the difference.

## Publication-grade text

Treat papers, manuscripts, abstracts, submissions, and other formally
published or evaluated text as publication-grade unless the user opts out.
The user may also explicitly apply this gate to another artifact.

Before finalizing or editing publication-grade text, perform a read-only
assessment. Include only the non-empty sections below:

- **Intent** — the understood purpose, reader, and claims.
- **Risks** — material ambiguity, terminology, explicitation, or semantic
  drift that needs attention.
- **Preview** — the full candidate for a short passage, or representative
  passages for a longer document.
- **Questions** — only decisions that affect the final text.

Place every blocking question under **Questions**. Stop after the assessment
and wait for explicit confirmation, even when that section is empty. Do not
edit a file or present the preview as final. After confirmation, complete the
editorial pass.

## Delivery

For a conversational result:

- Return one best version, without a heading, in a fenced code block whose
  delimiter cannot collide with its contents.
- Add concise notes outside the fence only for material explicitation,
  terminology choices, or suspected factual problems.

When the user explicitly requests a file edit, inspect the directly relevant
context and edit the file. Do not repeat the finished text in chat; summarize
the edited scope and report only material notes. The publication-grade gate
still applies.
